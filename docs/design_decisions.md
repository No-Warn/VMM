# 设计决策记录（阶段 1）

> 记录**为什么这么做**，以及**为什么没有做另一种**。每条都带证据来源；
> 证据要么来自本仓库实测（阶段 0 审计 / 阶段 1 实验），要么明确标注为外部方法事实。

---

## D1. 运动表示：复数可转向金字塔的**局部相位**，而不是结构潜变量 Δs

* **决策**：在连续视频的**像素域**做复数可转向金字塔分解，放大局部相位。
* **理由（本仓库实测）**：旧 `pyramid` 路线放大的是 FDM 的 Δs（32 维/patch、16×16 网格）。
  实测 `|Δs|/|s_A|` 基线仅 3.21%，且把 Δs 整体置零时解码输出像素只变 1–5/255 ——
  下游通道几乎不读它，放大再大也看不见。Δs 不是物理位移量。
* **被否方案**：把 Δs 当位移、或在潜空间做 warp（实测 latent 双线性插值伪影主导：
  0.8px 位移使 `‖warp(x_A)−x_amp‖²` 从 0.345 涨到 1.57）。
* **代价/局限**：相位只在**有线理**的区域有意义；低幅值像素的相位是噪声（见 D6）。

## D2. 用 `pyrtools.SteerablePyramidFreq(is_complex=True)`，而不是自研滤波器组

* **决策**：采用 pyrtools 1.0.11 的复数可转向金字塔（Simoncelli 构造）。
* **理由（实名实测）**：其重建自洽性 ``max|recon−img| = 3.82e-06``（96×96、4 层、3 方向），
  这直接决定 **α=0 的恒等能做到 1e-6 量级**，而不是"看着差不多"。
  且系数为复数 → 天然给出 ``A`` 与 ``φ``，正是相位式放大所需的最小表示。
* **被否方案**：自研 FFT 单演/Riesz 表示（零新依赖，但重建自洽性要自己担保，
  且要处理 DoG 带通之和是否为 1）。仍保留为**回退路径**（同接口，见 `vmm/phase_pyramid.py`）。
* **代价**：新增一个依赖；金字塔**逐级降采样**（最细层全分辨率、之后减半），
  故每带的相位定义在各自尺度上，逐带增益上限的含义不同（见 D6）。

## D3. 只存局部相位、重建时重新分解 —— 为了"真恒等"

* **决策**：第一遍逐帧只保留 ``φ``（float32）并算出 ``β=α·Φ_bp``；第二遍重新分解，
  把 ``exp(jβ)`` 乘到**原始复数系数**上。
* **理由**：若把 ``A``、``φ`` 都存下来再 ``A·e^{j(φ+β)}`` 重建，会引入 exp/angle 往返误差；
  现在 α=0 走的是"完全不改系数"的路径，恒等误差只剩金字塔重建误差（实测 2.1e-06）。
* **代价**：金字塔要算两遍（≈2× 时间），换来精确恒等与可控内存。

## D4. α 是**额外**增益，绝不是 FD4MM 的 m

* **决策**：``Φ_out = Φ + α·Φ_bp``；α=0 不放大，线性区总量 ≈ ``1+α``。
* **理由**：FD4MM 的 m 是数据集合成的**总倍率**，两者语义不同。混用会直接把 m=50
  当成"再放大 50 倍"，与期望的 (1+α) 差一个量级。任务书 §1 明确禁止。
* **落地**：`--alpha` 的 CLI 帮助与配置注释都写死这一点。

## D5. 时间带通：零相位 `butter+filtfilt`，只做离线

* **决策**：``butter`` 带通 + ``filtfilt``（双向、零相位），并显式校验奈奎斯特与周期数。
* **理由**：零相位保证**不引入额外时间位移**（否则"放大"里混进整体时移，无法区分）。
* **必须写对的细节**：``filtfilt`` 是双向滤波 → **有效幅频响应是 ``|H(f)|²``**，
  所以理论增益是 ``1+α·|H(f)|²`` 而不是 ``1+α·|H(f)|``（项目里通带中心 |H|≈1.000，数值相同，
  但定义必须写对，见 `vmm/temporal_filter.py::bandpass_gain_at` 的 `passes` 参数）。
* **代价（必须声明）**：使用未来帧 ⇒ **不是实时算法**。实时化（因果滤波）会引入群延迟，
  属后续工作，本阶段不做也不宣称。

## D6. `phase_clip` 默认 **None**（不限制），并配套一个消融实验

* **决策**：阶段 1 默认不设相位上限，以便**如实测出算法本身的增益**；真实视频建议显式给 1.0~1.2。
* **理由（消融实测，α=10、shm_h）**：不加限制时 β 可达 **34.9 rad**（主要来自低幅值像素），
  输出出现形变；加 1.0 rad 上限后**增益与波形保真同时改善**（相关 0.167→0.809）。
  若一开始就把上限藏进默认值，就测不出"算法本身能放大多少"。
* **接口预留**：``amp_floor``（低幅值系数限幅）与 ``max_gain`` 已就位，供阶段 2 的可靠性门控使用。

## D7. 多估计器交叉验证 + 用真值甄别主估计器

* **决策**：同时用 ``pc_plain_mean / pc_plain_first / pc_pyr_mean / pc_pyr_first / lk_first``
  五套测量，合成数据上用真值（±15%）甄别可信者并选主估计器；真实视频上报**分歧范围**作为不确定度。
* **理由（实测，这是本阶段代价最大的教训）**：**没有单一赢家**——
  干净带限序列上 `plain` 准（0.4976 vs 真值 0.500）而 `pyr` 低估 3 倍（0.1724）；
  带噪序列上反而 `pyr` 准（0.5188）、`plain_first` 高估 25%（0.6253）。
  若只用一个估计器，会得到互相矛盾的"结论"（我一度据此误判"增益饱和到 5"，实际是估计器退化：
  换 LK 后 α=10 测得 10.47，理论 11）。
* **另一条实测事实**：微运动序列的**时间平均帧被运动模糊**，参考帧纹理被抹掉后精度下降
  （干净序列波形相关 0.815，同样运动加噪后反而 0.986）→ 参考帧默认改**首帧**。

## D8. 度量必须自洽：灰度一律 Rec.709；接近零运动只报绝对误差

* **决策**：``metrics._gray`` 与 ``video_io.to_gray`` 共用 Rec.709 权重；任何"比值"在
  分母低于 ``ENERGY_FLOOR`` 时返回 ``nan`` 并要求调用方改报绝对值。
* **理由（两个实测坑）**：
  ① 早期 `metrics` 用三通道简单平均、而输出灰度是 Rec.709 ⇒ 真实视频 α=0（严格恒等）
  的能量比却报 0.95；② 完全静止背景的输入能量≈0 ⇒ 比值爆到 1e8，看起来像"放大了一亿倍"。
  任务书明确要求"接近零运动应报绝对误差，而不是计算不稳定的比例"。

## D9. 保持旧栈不动，不改默认行为

* **决策**：新代码放独立包 `vmm/`；`configs/amplifier/*`、`models/amplification/*`、
  `pretrained/dila_video_vmm.py` 一律不改不删；旧检查点与日志保留。
* **理由**：任务书 §1 的禁止事项与 §三.3（"暂时不要删除 DiLA 的旧代码"）。
  且仓库有 **141 个已跟踪文件未提交 + 整个放大器栈是未跟踪状态**（阶段 0 审计），
  任何"顺手清理"都可能造成不可恢复的损失。
* **回归门**：`tests/test_amplifier.py`（18 例）在每次改动后都必须继续通过。

## D10. 本阶段**明确不做**的事

| 未做 | 原因 |

| 训练任何网络 | 任务书：传统基线未通过验收前不得训练 |
| 可靠性门控 / 去噪 | 属阶段 2；其收益已由 D6 的消融量化 |
